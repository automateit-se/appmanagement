First release of App Management: one place to install, configure and update IoT Open Edge Apps on your installations, and to run an IoT Open Docker Edge Client for them. It looks and signs in like the IoT Open Dashboard; IoT Open stays the master for users, permissions, apps and installations.

## New

- **Sign-in with IoT Open:** e-mail and password with two-factor authentication, or an API key. The server is chosen on the sign-in page, as in the dashboard.
- **Installed apps per installation** (*Installerade appar*): every edge app on the installation with its version, *Ny version* when a newer one exists, *Uppdatera* with the current settings, *Inställningar* and *Ta bort*.
- **Catalogue** (*Lägg till app*):
  - Edge apps on GitHub: repositories with the topic `iotopen-edge-app`, and IoT Open's own apps (`IoTOpen/edge-app-*`, `GITHUB_INCLUDE`).
  - Apps that already exist in IoT Open (*Finns i IoT Open*).
  - A GitHub app that another organization already publishes in IoT Open (e.g. IoT Open's public apps) is installed from there, so no copy is made in your organization (*Publicerad i IoT Open av …*).
- **One-click install from GitHub:** App Management creates the app in IoT Open when needed (private to the organization), uploads `app.lua` and `app.json` for the chosen release and publishes it. Name, category, description and tags come from `edge-app.json` (IoT Open's convention) or from the repository and its README; the user never handles the files. A repository without releases installs its latest commit.
- **Settings form from `app.json`:** every input type in IoT Open's documentation: text (also multiline, with validator), number, option, checkbox, toggle (also with named values such as *under*/*over*), function and device selectors (also with a value per selected function), notification output selectors and repeat. Required fields and limits are checked before saving, and *Avancerat (JSON)* shows the exact config.
- **IoT Open Docker Edge Client** (*Edge client*): *Sätt upp edge client* starts `ghcr.io/iotopen/edge-client` for the installation in the same Docker environment. Its credentials are created through the IoT Open API and written straight into the edge client's own volume; they never reach the browser. The page shows whether it runs, its log with errors highlighted, and has *Stoppa*, *Starta*, *Starta om*, *Uppdatera*, *Nya credentials* and *Ta bort*. Setting up and updating run in the background with their progress on the page.
- **Edge status from IoT Open:** App Management reads whether the installation already has an edge client and whether it is online (as Lynx shows *Edge status: Online*). If one is online, setting up a new one shows a clear warning and must be confirmed, since IoT Open keeps one set of credentials per installation.

## Deployment

- One container (web app and a small Node backend without dependencies) plus `docker-socket-proxy` for the Docker access, see `deploy/compose.yml` and `deploy/env.example`. Edge clients run as sibling containers on their own network, `iotopen-edge`.
- `EDGE_ADMINS` decides who may manage edge clients, `GITHUB_OWNERS` and `GITHUB_INCLUDE` which GitHub apps are listed. See `SECURITY.md`.

Images: `ghcr.io/automateit-se/appmanagement:0.1.0` (amd64 and arm64).
