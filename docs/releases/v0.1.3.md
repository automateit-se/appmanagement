# App Management 0.1.3

## Changes

- Setting up a new edge client, which starts a new container on the server, can be limited to users whose IoT Open role has a particular permission. Give a dedicated role in IoT Open a permission of its own and set it as `EDGE_PERMISSION` in `.env`. As before, IoT Open's roles decide: the permission is read from the user's role, also when signing in with an API key.
- Looking at, starting, stopping, restarting, updating and removing an existing edge client follow the user's IoT Open role as before and do not need the extra permission.
- `EDGE_ADMINS` now also applies only to setting up new edge clients. `EDGE_PERMISSION` and `EDGE_ADMINS` can be combined; both then apply.
- Users who may not set up an edge client are told why: their role, or that this server requires a role with a particular permission.

## Upgrade

Download `deploy/compose.yml` again (it passes `EDGE_PERMISSION` on), set `APPMANAGEMENT_TAG=0.1.3` and optionally `EDGE_PERMISSION` in `.env`, then `sudo docker compose pull && sudo docker compose up -d`.
