# App Management 0.1.13

## New

- **What an update changes in the settings.** The update dialog compares the settings of the installed version with those of the new one and shows:
  - **New** settings, with the value they will get (their default), and those that must be filled in.
  - **Changed** settings: a new default, new limits, new or removed choices, another type, or now required. It also says whether the current value is still accepted, for example *Högst 720* when the maximum went down.
  - Settings that **disappear**, with the value they have now. They are removed from the app's settings on update instead of being left behind.
  - **Unknown** settings: values in the app's settings that neither version's form has. They are kept as they are.

  New and changed settings are also marked *Ny* and *Ändrad* in the form. Passwords are never shown. If the installed version's settings cannot be read, the dialog compares with the current values instead and keeps anything it cannot place.
- **Install next to the old version.** An app with a newer version gets *Installera bredvid*: the new version is installed as an app of its own, named after the old one with its version, with the old one's settings copied (and the same comparison shown). The old one keeps running and still shows that a new version exists. The dialog points out that both run at the same time and may clash, for example on the same port, functions or MQTT topics.

## Upgrade

`sudo appmanagement-update`, or by hand `APPMANAGEMENT_TAG=0.1.13` in `/opt/appmanagement/.env`, then `sudo docker compose pull && sudo docker compose up -d`.
